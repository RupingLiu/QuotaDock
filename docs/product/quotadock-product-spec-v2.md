# QuotaDock Product Spec v2

> 状态：v0.5.4 基线
> 更新日期：2026-08-06

## 1. 产品定义

QuotaDock 是 Windows 常驻 Codex 额度状态工具。它用一个可拖动的紧凑状态条回答：
“当前 1 周额度还剩多少、何时重置、这个数字是否可信？”

产品不是通用用量分析平台，也不替代 Codex 官方 Usage Dashboard。官方页面是
权威核验与故障兜底，QuotaDock 的价值是低打扰、随时可见和失败可解释。

## 2. 目标用户与核心任务

- 在 Windows 上持续使用 Codex CLI，希望避免额度耗尽打断工作的个人用户。
- 需要在不切换浏览器或终端的情况下扫一眼剩余额度。
- 当自动查询失败时，需要知道当前显示的是旧值、失败原因和可执行的排查信息。
- 希望自行决定是否开机启动、自动检查更新和接收低额度通知。

## 3. 核心体验

### 3.1 常驻状态条

- 固定设计尺寸 `260 × 36px`，显示周额度百分比、紧凑重置时间、新鲜度与菜单。
- 支持拖动、屏幕边缘吸附、跨显示器坐标和位置恢复。
- 明确区分 fresh、busy、error、stale、warning、empty 与低额度状态。
- 失败时保留最后一次成功值，但不得把旧值表现为本次成功。

### 3.2 详情与控制

- 展示完整重置时间、数据来源、最后成功时间、存储状态和最近趋势。
- 展示 QuotaDock/Codex 版本、可执行文件路径和状态文件路径。
- 提供手动刷新、开机启动、自动更新、低额度通知开关。
- 提供固定 Codex 官方 Usage Dashboard 入口。
- 存储恢复提示必须持续显示，直到用户明确确认。
- 启动后及每 6 小时在后台检查更新；发现新版后静默下载并验证签名，完成时使用不抢焦点的系统通知和页内状态提示。
- 自动更新只负责准备经过验证的安装包，必须由用户主动点击“立即安装”后才执行安装和重启。

### 3.3 托盘

- 显示/隐藏状态条、打开详情、刷新额度、打开官方页面。
- 动态展示并切换开机启动、自动检查更新和低额度通知。
- 单实例：第二次启动只唤醒现有实例，不创建重复托盘或查询线程。

## 4. 数据与可靠性

1. 主数据源为 Codex App Server `account/rateLimits/read` 的结构化 JSONL 协议。
2. 结构化查询失败时，才使用隐藏 PTY 的 `/status` 文本解析兼容层。
3. 有效周额度窗口至少要求剩余百分比；只有重置时间不能视为成功用量。
4. 自动刷新必须防重入，并按正常、低额度、临近重置和连续失败自适应调度。
5. 状态写入采用临时文件 + 原子替换。格式损坏或版本不兼容时先备份再恢复。
6. 历史只保存百分比与时间，不保存原始终端输出；最多 672 个稀疏采样点。

## 5. 信任、隐私与安全

- 不读取或保存 Codex 认证文件、令牌和原始 App Server 响应。
- 更新包必须通过内置 Ed25519 公钥验证，并将安装包内嵌 ProductVersion 与清单版本绑定；未签名、签名不匹配、版本回放或低于本机最高可信版本时拒绝安装。
- 更新清单只允许配置的项目 Release 端点；WebView 使用最小 CSP。
- 默认使用当前用户安装模式，避免无必要的管理员权限。
- 低额度通知默认关闭；开启前遵循 Windows 权限状态。
- Authenticode 与应用内更新签名是独立信任链；无证书时必须在发布说明中透明披露。

## 6. 功能取舍

### 保留

- 周额度、重置时间、新鲜度、旧快照、托盘、位置保存与自适应刷新。
- 轻量诊断、可选通知和小型趋势：它们能直接解释“数字是否可信”。

### 合并

- 所有刷新入口进入同一个协调器。
- 后台设置与托盘菜单使用同一份持久化设置。
- 数据源统一为结构化主适配器 + PTY 降级适配器。

### 暂不新增

- 完整分析图表、备注、导出、剪贴板监听。
- Spark 多模型额度、API Billing、组织/Enterprise 账单。
- macOS/Linux；当前产品基线明确为 Windows。
- 手工粘贴 `/status` 主流程。若未来恢复，只能作为显式故障降级。

## 7. v0.5.4 验收标准

- 前端单测、Svelte/TypeScript 检查、生产构建全部通过。
- Rust 单测实际执行通过，不只生成测试二进制。
- 本机真实 Codex App Server 周额度查询成功，且来源标记为 `codex-app-server`。
- 状态 schema v4 的快照与历史只保存周额度；损坏恢复提示与设置可跨重启持久化。
- `260 × 36px` 状态条在浅色、深色与系统缩放下无截断，旧版本靠边位置迁移后仍贴近原屏幕边缘。
- 自动检查不显示模态框、不抢焦点；安装包只有在验签、内嵌版本与原子缓存均成功后才能进入“已准备”状态。
- 相同版本不重复下载或重复通知；下载、验签与安装竞态受同一更新操作锁保护，较低版本不能覆盖已验证的更高版本。
- 签名安装包能生成 `.sig`；`latest.json` 同时包含 Tauri `signature/url`
  和旧版本需要的 `sha256/size/filename`。
- 发布资产摘要与本地生成值一致；远程 Release 标记为非草稿、非预发布。

## 8. 后续评估

- 收集结构化查询失败类型，而不是收集额度数值或账户标识。
- 根据真实请求评估是否需要可配置阈值、趋势导出或企业部署包。
- 在获得可信 Authenticode 证书后，为安装器和主程序增加 Windows 代码签名。
