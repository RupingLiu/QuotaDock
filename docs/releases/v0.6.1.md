# QuotaDock v0.6.1

## Kimi Coding Plan

- 撤回错误的 Kimi API 开放平台余额实现，改用 Kimi Code 官方客户端同源的 Coding Plan 用量接口。
- 展示套餐总用量，以及 Code 的 5 小时、7 天等官方实际返回窗口、精确 used/limit 和重置时间。
- 顶层总量不硬编码成“月”或“周”，按接口实际 reset time 原样展示；会员月总额度仍以官方订阅页为准。
- 悬浮条保持 `260 × 36px`：主值显示总剩余，副值显示当前剩余最少的 Code 窗口；完整窗口留在详情页。
- Kimi 与 Code 在官方页面中的总量分段没有公开稳定字段，QuotaDock 不抓取网页或猜测分项，提供固定 Kimi Code 官方入口供核对。
- Kimi Code API Key 使用独立 Windows Credential Manager 条目，不读取或复用 Moonshot API Key。
- v0.6.0 若已保存旧 `kimi-cn-api-key`，升级不会读取也不会代删；可在 Windows 凭据管理器中手动清理。

## 轮播与 DeepSeek

- 修复状态 revision 或新鲜度更新反复重置 8 秒定时器、导致悬浮窗看似永不轮播的问题。
- 鼠标点击供应商与菜单不会遗留焦点暂停；键盘焦点、悬停、页面隐藏和减少动态效果仍按设计暂停。
- DeepSeek 悬浮项中的“充值余额”现在可点击，直接打开固定官方充值页，同时避免触发窗口拖动。

## 升级与安全

- 状态升级到 schema v6。v5 的 Codex、DeepSeek、趋势和设置会保留；错误口径的 Kimi API 余额会清除，需重新保存 Kimi Code API Key。
- 供应商请求继续使用固定 HTTPS 端点、系统代理、超时、64 KiB 上限、禁重定向和脱敏错误。
- 自动化测试不访问真实账户或 Windows Credential Manager；正式数值仍以官方 Kimi Code 控制台、DeepSeek 平台和 Codex Usage 页面为准。
